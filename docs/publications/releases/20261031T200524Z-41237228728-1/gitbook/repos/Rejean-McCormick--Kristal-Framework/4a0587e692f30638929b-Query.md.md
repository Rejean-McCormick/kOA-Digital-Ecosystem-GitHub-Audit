# Query — Kristal Query Protocol (KQP)

**Protocol:** `kristal-query/1.0`

KQP is the v8 machine contract for AI-oriented **read query**. It retrieves and projects canonical semantic material; it does not decide truth and does not create authority.

## Request

A request can declare:

- `query_id` and query mode;
- semantic roots;
- optional discovery method;
- namespace/Kristal/shard/source scope;
- typed traversal direction and property constraints;
- semantic/status/source filters;
- evidence policy;
- pagination/continuation cursor;
- hard resource budget;
- optional lexical rendering request;
- output encoding preference.

Free-form intent may guide ranking but cannot override typed constraints.

## Budget

Portable hard limits include:

- `deadline_ms`;
- `max_items`;
- `max_nodes` / `max_edges` where relevant;
- `max_bytes`;
- optional `max_tokens` only with a declared `tokenizer_id`.

Child/federated queries consume the parent budget; they do not receive a fresh independent budget.

## Result

A result declares:

- normalized execution plan;
- source-state fingerprints;
- resolved roots / discovery candidates;
- returned semantic material;
- conflicts / unresolved items;
- `status: complete|partial|error`;
- semantic/evidence/source completeness;
- truncation reasons;
- continuation cursor;
- explicit omissions.

`partial` means useful but incomplete. It must never be interpreted as a negative answer about omitted material.

## Derived status

KQP results, indexes and plans are read models:

```text
QUERY INDEX != SOURCE OF TRUTH
QUERY PLAN != ASSERTION
PARTIAL RESULT != NEGATIVE RESULT
```
