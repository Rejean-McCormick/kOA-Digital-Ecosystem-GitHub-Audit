# Known limitations and non-goals

This page lists deliberately constrained behavior **and** gaps verified through the 0.15.0-alpha.1 source/validation notes.

## By design

1. **No data acquisition bootstrap.** Skope does not download a Wikidata dump, construct a compact index or generate missing random-access sidecars.
2. **No automatic canon writes.** Kristal workspaces and historical EncyK source products are not modified by Skope campaigns.
3. **No automatic scope execution.** JSON catalog refresh and Kristal selection remain separate from start actions.
4. **Limited preview.** Graph preview has a 10,000-node memory/HTTP budget.
5. **No batch geography exclusion or convergence.** These are preview/review concepts; QID collection uses explicit graph traversal only.
6. **No source claim verification by indexing.** The compact graph aggregates relationships, omitting original statement IDs and qualifiers.
7. **No externally authenticated identities.** Candidate ranking is heuristic and documentary URLs are not fetched/checked online.
8. **No automatic campaign replay after identity review.** Resolved people do not silently cause new work collection or JSON extraction.

## New portfolio-specific limitations (0.15.0-alpha.1)

- **CLI only**; the existing browser UI has no portfolio dashboard or live bulk-progress controls.
- **Not a semantic enrichment autopublisher:** no integrated diK approved-crosswalk transaction, canonical KA creation or Authoring Kit publication.
- **Bounded matching:** exact-term uniqueness among search hits does not prove conceptual identity. Draft seeds are non-approved and excluded for `A-Kristal`; claims emitted from such seeds stay explicitly unverified.
- **Sparsely labeled projects:** 81 of the 104 supplied example projects lack curated domain search seeds and need separate scope/root discovery.
- **Production source not tested here:** no real large-scale `D:` index/full-dump portfolio run or throughput benchmark was executed for 0.15.0-alpha.1.
- **Existing verified source required:** source profile, original dump and fast locator must already work; Skope does not download/scan/reindex a missing Wikidata dump.

## Environment-dependent limitations

- The supplied extraction profiles use installation-specific `C:`/`D:` paths and a historical dump filename. They are not portable defaults for arbitrary environments.
- Real local disk, memory, reader, backup and Windows UI behavior must be tested **on the operator's machine**.
- The software is a local single-instance research tool, not a supported multi-user/web-hosted service. Loopback restriction does not replace access control.

## Legacy documentation / implementation notes

- `VERSION` and API server release identify **0.15.0-alpha.1**, and `pyproject.toml` declares **`0.15.0a1`**.
- Historical `README.md` / `README_FR.md` headings still describe 0.14.x milestones, followed by appended 0.15 release content. Do not interpret those older headings as the current code version.
- `contracts/scope.recipe.schema.json` is labeled with older proposal metadata; runtime code adds constraints not captured there. Clarify/version the public schema before presenting it as canonical.
- `tests/test_density_dom.cjs` depends on packages not declared in a `package.json` in the archive, so it cannot run from a clean checkout without additional setup.
- The HTTP Host parser in `skope/api.py` rejects a typical bracketed IPv6 host such as `[::1]:8767` despite permitting `::1` at server startup. Use `127.0.0.1` until that parser is corrected.
- Existing compression sidecars in pickle format are loaded using `pickle.load`; those local files must be considered trusted pipeline inputs.
- Extraction checks dump-manifest/sidecar identity but does not explicitly cross-check the dump SHA-1 against the compact index `meta.dump_sha1`; comparing both snapshots would strengthen provenance.

These remaining discrepancies are **documentation/operational limitations**, not evidence that the backend's declared `SERVER_RELEASE` is different.
