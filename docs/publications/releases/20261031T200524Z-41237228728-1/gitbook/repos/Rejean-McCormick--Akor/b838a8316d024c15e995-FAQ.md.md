# Frequently Asked Questions

## Is Akor only a technical connector?

**No.** Connecting software is how Akor supports its main purpose: **bringing children together through meaningful interaction, cooperation and shared problem-solving**. The human accord is the reason for the architecture.

## Is Akor a replacement for Kontexte or kompose?

No. Kontexte owns scenario design; kompose owns deterministic preview and coordination rules. Akor integrates their reviewed outputs into an authorized learning experience without taking over their source models.

## Will Akor run its own missions independently of Orgo?

Not under the current architecture decision. **Orgo remains the only live operational state owner, including solo work.** Akor does not run a parallel task/Case/Signal engine.

## Is Orgo_Worlds part of Orgo?

It is a separate repository with its own canonical World and WorldRelease responsibilities. It is not a second operational workflow engine.

## Can Akor let a child work alone?

The target design supports solo mode using Orgo's same operational model. It should never impersonate human peers or fabricate their evidence. The end-to-end solo Akor path is not yet delivered.

## Does a shared score prove cooperation?

No. A collaborative mission should include purposeful exchanges and individual contributions; group completion and subject mastery are different facts.

## Do pupils have to chat online?

No. Face-to-face conversation, teacher-facilitated exchange, manipulatives, and structured messages may all support collaboration. Any digital peer communication requires child-safety design and governance.

## Is the bakery mission ready for children?

No. Its source status explicitly requires pedagogical review, it still references addition (`qc-pri-ma-006`), and the Orgo enforcement of role fragments and joins is not yet qualified.

## Does Akor have a Git repository or live API today?

Not yet as part of this documentation. A local, read-only prequalification bridge exists; creating the `akor` repository and implementing its runtime adapters are future tasks.

## Can we test it without real student data?

Yes, and we should. Use version-pinned repositories, synthetic missions, fictional identities, and an isolated Orgo test world. Cross-client tests must precede any real classroom pilot.
