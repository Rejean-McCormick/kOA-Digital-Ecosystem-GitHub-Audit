# 18 — Optional portable AI capsule

`kristal.portable-ai/1.0` is a **derived** reader model for offline consumption by an AI or a read-only tool such as Kompiler. It is not generated by a plain `build-v9` unless explicitly requested.

```bash
python tools/kristal.py build-v9 .
python tools/kristal.py build-ai .
python tools/kristal.py check-ai .
python tools/kristal.py pack-ai . --output portable-reader.zip
python tools/kristal.py read-surface . --require-ready
```

`build-v9 --with-ai` is available as an explicit alternative. `build-ai` creates an exact copied v9 State Snapshot, `AI_MANIFEST.json`, `ai/INDEX.json`, a coverage report, contextual reading aids, and materialization descriptor inventory. External materialization locators are reported but **never downloaded**.

## Readiness is verified, not guessed

An existing `AI_START_HERE.md` or `AI_MANIFEST.json` is not proof of readiness. `portable_ai.enabled=false` controls the normal default generation/check behavior; stale AI files may still exist. `check-ai` and `read-surface --require-ready` must independently reject missing, corrupted, out-of-workspace, duplicated or incorrect-size indexed files. Reader projection digests are distinct from Logical/State Commitments and are not authorization for transport.

`ai/COVERAGE.json` distinguishes available workspace-local blobs, missing workspace-local locators, external references and partial availability; absence of a blob is not logical negation. Build/read results remain derived and removable. GitHub, Python, Node or an active connection are not required to **read** a completed portable capsule.
