# 07 — V9 validation and independent qualification

## A. Workspace envelope

Verify required file structure, identity, format, status, ownership, State Index, source catalog, and candidate native model without claiming semantic truth.

## B. Domain and epistemology

Define contract-specific invariants, provenance rules, observations versus hypotheses, conflict treatment, and scope. A generic Kit cannot adjudicate all domains.

## C. Logical Commitments

For each Logical Artifact, verify the exact declared logical contract and computed or precomputed commitment profile. A byte SHA is not automatically a Logical Commitment.

## D. State Commitment

Check deterministic state membership and pinned references. Hosting location, Git SHA and projections must not affect this semantic commitment.

## E. Materialization

Validate descriptor structure, source binding, declared reconstructability, blob paths and actual SHA/size for local available bytes. External bytes may remain unresolved without being asserted false.

## F. Independent qualification

KristalDiag/C1 must qualify the exact state/revision under a separately owned process. Local `check`, `inspect`, `build-ai` and Framework schema validation are not independent scientific/factual qualification.

## G. Release

An immutable local release and a hosted v10 publication are different workflows. Public synchronization itself requires authorization before the first network write. C2 grants, C3 collection integrity and final activation are separately verified.
