# Installation Windows et prérequis

## Environnement observé

Utilisateur Windows avec PowerShell 7; les sources locales habituellement dans `C:\mycode\Kristal\locals\` et Manager dans `C:\mycode\Kristal\Kristal-Manager\`. Le snapshot Manager et KristalDiag indiquent Python 3.11+, le moteur Diag exige `jsonschema>=4.20`. Les profils de publication peuvent demander des dépendances séparées, mais ne sont pas nécessaires à un inventaire local.

## Avant d'installer une nouvelle refonte

- Fermer Manager et tous les processus Diag.
- Vérifier le contenu du ZIP et son manifeste, le chemin exact d'extraction et les conflits.
- Sauvegarder Manager, le petit SQLite opérationnel, les registres de revue et les preuves.
- **Ne pas** extraire un overlay de Manager dans `locals` ou un overlay de Kristals dans `Kristal-Manager`.
- Ne pas remplacer un module plus récent sans comparer les hashes et les changements locaux.

## Contrôles PowerShell non destructifs

```powershell
cd C:\mycode\Kristal\Kristal-Manager
python --version
python -c "import jsonschema; print(jsonschema.__version__)"
Test-Path .\tools\KristalDiag\kristaldiag.py
Test-Path .\kristal_manager\central_store.py
Test-Path .\catalogue\kristal-manager-operations.sqlite3
```

`Test-Path` sur SQLite retourne `False` si aucun run n'a encore créé l'index : ce n'est pas une anomalie en soi.

## Politique PowerShell

Les scripts `.ps1` extraits d'un ZIP peuvent être bloqués par la politique Windows. Préférer les commandes Python ou des scripts signés en production; une autorisation temporaire `-Scope Process` est une décision locale explicite, jamais un prérequis forcé par l'installateur.

## Distribution cible

Manifeste SHA-256, version exacte, dépendances, README de migration et retour arrière, smoke tests, exclusion des bases générées et données privées. Aucun `git push`, `.bat` de publication ni démarrage automatisé de scanner à l'installation.
