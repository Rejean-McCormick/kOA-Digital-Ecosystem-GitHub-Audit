# Integrated Systems

> **Reading model:** The main path explains what the kOA ecosystem enables. The technical reference explains how kOA-Linux hosts, isolates, verifies, and operates those capabilities. Product-specific details remain in each subsystem's own documentation.

Ariane, Konnaxion, Orgo, SenTient, and SemantiK Architect retain their own product authority and documentation. kOA-Linux owns only their operating and integration boundaries.

| System | Role | Product documentation |
| --- | --- | --- |
| Ariane | semantic navigation and interaction orchestration | [public overview](https://initkoa.org/technology/ariane) |
| Konnaxion | public learning, collaboration, deliberation, culture, and collective intelligence | [Wiki](https://github.com/Rejean-McCormick/Konnaxion/wiki) |
| Orgo | organizational execution and operational continuity | [Wiki](https://github.com/Rejean-McCormick/Orgo/wiki) |
| SenTient | optional semantic reconciliation workbench | [repository](https://github.com/Rejean-McCormick/SenTient) |
| SemantiK Architect | deterministic multilingual realization | [Wiki](https://github.com/Rejean-McCormick/SemantiK_Architect/wiki) |

Kristal Runtime is a local internal runtime boundary around independently developed Kristal artifacts and tooling. UCKK is an external platform, not an integrated local subsystem.

kOA-Linux boundary ownership includes deployment, resources, identity, trust, storage exposure, network access, lifecycle compatibility, health, offline behavior, backup coordination, and safe degradation.
