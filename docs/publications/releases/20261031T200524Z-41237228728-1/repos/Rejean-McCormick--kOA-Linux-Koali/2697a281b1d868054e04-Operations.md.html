# Operations

> **Authority notice:** This wiki is a readable navigation layer. Source contracts, accepted ADRs, normative documents, and executable validators in the repository remain authoritative.

## Operating model

Operations preserve declared authority, evidence, recoverability, resource bounds, and profile-specific guarantees. A node remains locally authoritative for final admission and sensitive host mutations.

## Operational domains

| Domain | Main concerns |
| --- | --- |
| Observability | Health, readiness, events, receipts, metrics, and bounded diagnostics |
| Resources | CPU, memory, I/O, concurrency, queues, scheduling, and capacity |
| Continuity | Offline operation, safe degradation, backup, restore, and disaster recovery |
| Incidents | Detection, containment, evidence, repair, communication, and recourse |
| Maintenance | Verified updates, storage care, key rotation, cleanup, and lifecycle tasks |
| Profile operations | User-lightweight, sovereign-node, hub, control-plane, and build-farm procedures |

## Backup and restore

Backups preserve authoritative data, contracts, keys or key references, manifests, provenance, and verification evidence according to the active profile. Restore is tested and does not silently merge incompatible authority states.
