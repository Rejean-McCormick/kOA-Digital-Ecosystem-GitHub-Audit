# Version Stack: v6 → v7 → v8 → v9

**Historical v9-focused view.** For the current additive hosted-network layer, see [[Version-Stack-v6-v7-v8-v9-v10]].

Kristal versions are best understood as a stack of responsibilities, not as mutually exclusive generations.

## v6 — portable epistemic state

V6 defines the portable truth artifact `kristal_state/6.0` and its epistemic substrate:

- independently addressable assertions;
- valuations/value states;
- coordinates and applicability;
- record roles and actionability;
- evidence/provenance;
- validation/recognition;
- conflict/supersession and lineage;
- deterministic canonical identity.

## v7 — semantic identity and orchestration

V7 adds stable opaque namespaces and cross-Kristal structure:

```text
KQ… entity/item
KP… property/relation
KA… assertion
KS… source
```

It also introduces assertion families, factorization, typed Mesh/axes, KOS mappings and projections.

```text
SEMANTIC IDENTITY != CONTENT IDENTITY
```

## v8 — language and exact query/read models

V8 externalizes lexicalization and formalizes AI/query access:

- lexical Kristals and stacks;
- exact KQP query;
- rebuildable indexes;
- bounded AI context bundles;
- semantic fingerprints distinct from byte hashes;
- explicit partial/completeness semantics.

```text
SEMANTICS != LANGUAGE
READ MODEL != CANONICAL STATE
```

## v9 — semantic state architecture

V9 adds representation-independent state and lifecycle:

- Logical Artifact;
- State Snapshot;
- Logical Commitment;
- Derivation;
- Materialization;
- Exchange;
- Runtime Pack binding;
- Build / Publish / Activate;
- pinned federation and coverage.

```text
LOGICAL STATE != PHYSICAL MATERIALIZATION
```

## Compatibility rule

A valid inherited artifact does not need to be rewritten merely to participate in v9.

```text
V9 ADOPTION != V6/V7/V8 REWRITE
```

See [[Compatibility-v6-v7-v8-v9]].
