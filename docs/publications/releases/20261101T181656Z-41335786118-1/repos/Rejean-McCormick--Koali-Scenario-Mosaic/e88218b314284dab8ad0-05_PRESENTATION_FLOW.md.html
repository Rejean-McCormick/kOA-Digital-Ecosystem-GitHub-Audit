# Recommended presentation flow

## 1. Open with the fragmentation problem
“Knowledge is somewhere, discussion somewhere else, decisions in meetings, work in another tool, and memory in people’s heads.”

## 2. State the promise
> **Koali connects knowledge, people, choices, work, and memory.**

## 3. Show the eight-color usage palette
Keep it human-facing. No module architecture yet.

## 4. Show 12 contrasting hero scenarios
Use very different sectors and scales so breadth is felt before it is explained.

## 5. Reveal the invariant
`understand → people → choice → work → outcome → memory`

## 6. Introduce the 24 recurring patterns
This explains why apparently unrelated examples belong to the same system.

## 7. Introduce Kristal, Konnaxion, Orgo, and UCKK
Now the architecture answers a question the reader already has.

## 8. Open the 120-scenario Atlas
Let readers filter from their own need, not from Koali jargon.

## 9. Add differentiating properties
Offline, multilingual, local-first, AI-optional, sensitive-data, public-facing, high-consequence boundaries.

## 10. End on continuity
> **Koali is not specialized in one profession. It is specialized in the transitions between knowledge and coordinated action.**
