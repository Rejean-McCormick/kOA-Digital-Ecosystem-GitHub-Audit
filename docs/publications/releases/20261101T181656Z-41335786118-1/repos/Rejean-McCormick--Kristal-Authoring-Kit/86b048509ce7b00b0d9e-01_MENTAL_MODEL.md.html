# 01 — Mental model

## 1. A Kristal is not a single database type

A Kristal is a durable unit of semantic memory with identity, boundary, provenance, and reading rules. Its native form depends on the domain. A Kristal may organize referents and assertions, structured domain payloads, procedures, state machines, proofs, observations, hypotheses, decisions, executable models, references to other Kristals, and reproducible projections.

## 2. Four distinct layers

### A. Kristal identity

The unit has a name, scope, owner, parentage, and lifecycle. It may exist as an empty identity **stub** before canonical domain content is admitted.

### B. Semantic payload

The native, domain-owned knowledge at a specified state. This can be a graph, a formal theory, a procedure or another polymorphic structure.

### C. V9 Logical Artifact and State Snapshot

Each Logical Artifact commits logical content under an explicit contract. A State Snapshot composes members and pinned references without prescribing their physical packaging.

### D. Surface, projection, runtime

A Surface is a reader-oriented view; a Projection materializes a reading, while Runtime Packs optimize access without becoming the canon.

## 3. The core standardizes distinctions, not topology

```text
IDENTITY != LABEL
REFERENT != ASSERTION
COORDINATE != APPLICABILITY
PROJECTION != SOURCE
READ MODEL != CANONICAL STATE
SIMILARITY != EQUIVALENCE
AI PROPOSAL != ACCEPTED STRUCTURE
MODEL OUTPUT != AUTHORITY
LOGICAL STATE != PHYSICAL MATERIALIZATION
LOGICAL COMMITMENT != BLOB DIGEST
BUILD != PUBLISH != ACTIVATE
```

## 4. Native payloads remain open

Examples include invariants, graphs, multigraphs, hypergraphs, DAGs, sparse matrices, hierarchies, multiplex networks, automata, event ledgers, causal models, executable programs, formal theories, research memory, pedagogy and hybrid structures. This list is illustrative, **not** a closed registry of native kinds.

## 5. Assertions and domain payloads

Addressable assertions and epistemic envelopes do not require flattening recipes, n-ary reactions, structured evidence, workflows or theories into naive triples. Preserve the native domain object and its relevant source and authority.

```text
SEMANTIC ENVELOPE != FORCED DOMAIN SHAPE
```

## 6. Domain dimensions are not automatically v7 orientation axes

A native model can have many dimensions. A portable oriented projection has exactly **one primary axis** and at most **one secondary axis**. That limitation applies to the projection, not to the native domain.

## 7. Identity, revision, and bytes

Semantic identity identifies the subject and owner; a logical revision is bound by v9 commitments; physical bytes and Git transport can change independently when allowed by the relevant contracts. Neither a repository path nor a content digest replaces a State Commitment.
