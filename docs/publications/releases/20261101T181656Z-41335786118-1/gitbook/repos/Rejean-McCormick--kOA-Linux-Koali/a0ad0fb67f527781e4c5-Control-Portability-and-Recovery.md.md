# Control, Portability, and Recovery

> **Reading model:** The main path explains what the kOA ecosystem enables. The technical reference explains how kOA-Linux hosts, isolates, verifies, and operates those capabilities. Product-specific details remain in each subsystem's own documentation.

Sovereignty requires practical control over data, meaning, software, trust, and continuity.

The architecture therefore treats the following as tested capabilities:

- export of local data, knowledge artifacts, media manifests, policies, cases, tasks, and evidence;
- verification of exported packages;
- restoration on another compatible node;
- backup and recovery without permanent cloud dependency;
- trust-root and operator handover;
- revocation of former access;
- visibility into active versions and queued exchanges;
- preservation of source authority when artifacts move between systems.

Portability does not mean that every external platform database is copied locally. It means that selected, governed artifacts can move while preserving identity, provenance, rights, versions, and authority boundaries.
