# Concepts & Mental Model

Kristal v9 separates concerns that must not collapse into one artifact or authority.

## The five planes

1. **domain/epistemic knowledge** — v6/v7 or a v9 domain-native Logical Artifact;
2. **semantic identity/orchestration** — v7 KQ/KP/KA/KS, Mesh, KOS mappings and projections;
3. **language/query access** — v8 lexical Kristals, KQP and AI contexts;
4. **derivation/materialization** — v9 build lineage and physical representations;
5. **publication/activation** — immutable State Snapshots selected by operational channels.

## The three identities

```text
semantic ID      → which logical object?
logical commitment → which exact logical revision/content?
blob digest       → which exact bytes?
```

These are deliberately different.

## Native shape, common lifecycle

Kristal does not require every knowledge domain to share one data structure. The common architecture standardizes identity, integrity, provenance, composition and lifecycle while allowing the payload to remain domain-native.

## Accumulation

```text
source / observation / research
        ↓
domain-native canonical artifact(s)
        ↓
State Snapshot
        ↓
materializations + query/language/runtime projections
        ↓
human / AI use
        ↓
new candidate work
        ↓
validation / admission / publication boundary
```

The final boundary matters: model output, a query index or a runtime cache does not automatically mutate canonical state.
