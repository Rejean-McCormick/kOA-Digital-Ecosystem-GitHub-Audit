# Kristal v10: Discovery and Hosting

## What v10 introduces

Framework v10 **draft.3.2** extends the v9 model with a hosted-network architecture: node manifests, host bindings, read surfaces, collection indexes, and publication artifacts. The first hosting profile is `kristal.host/github/1.0`.

It does not automatically rewrite v9 logical commitments. A repository's Git SHA-1/SHA-256 identifier is not interchangeable with a State Commitment.

## Local and hosted reading are different paths

| Local | Hosted |
| --- | --- |
| Explicitly selected workspace directory | Indexes and references from a published/hosted collection |
| `kristal-local-catalog-v10` → `kristal-local-v10` | `kristal-v10` / GitHub adapters |
| Checks on files read from disk | Index and hosted-surface checks under the applicable profile |
| May use a configured local derived graph | Hosting view may be **technical only** |

Clicking **Open in Explorer** does **not** trigger automatic publication. Konstellation must not push the corpus or fabricate C1/C2/C3 evidence.

## Privacy boundary

Preparing a copy for public GitHub, even as a “temporary” synchronization, may expose private data as soon as it is transferred. The publication chain requires external authorizations and qualifications; `ready` on a read surface is not enough.
