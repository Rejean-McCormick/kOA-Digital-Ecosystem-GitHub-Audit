# Tandem Konnaxion ↔ Orgo — prioritized VPS Linux / Docker / Capsule Agent profile

**C0 coordination decision, 2026-10-18.** [Machine-readable profile](deployment-profile.json) · [Owner gates](acceptance.md) · [Evidence and limits](evidence-ledger.md) · [Decisions](decision-log.md).

**Owner:** kOA Digital Ecosystem records the decision and dependencies; **it does not deploy, admit, activate or authorize a release.** The user selected a **Linux VPS running Docker with the Konnaxion Capsule Agent** as the **first target**. This is *not* a declaration that the VPS, agent, domains, IdP or ReleaseSet have been configured. kOA-Linux is an optional alternative/additional profile, not a compulsory dependency for this first tandem delivery.

## Expected deployment boundary

```text
 operator / Capsule Manager  ── authenticated, typed operations ──▶ VPS Linux Capsule Agent (privileged PEP)
                                                                      │
 build & native diag evidence ── signed exact ReleaseSet ─────────────┤ measure target state independently
 KonnaxionDiag 4.2.5 verify-activation (trusted Ed25519 keys/policy) ◀──┤ deny missing/bad/expired proofs
                                                                      │ only after ADMIT
                                       Docker / Compose-owned staged Konnaxion and Orgo
                                           ├── Konnaxion data/services (owner)
                                           ├── Orgo data/services (owner)
                                           └── independent durable backup/restore, outbox fencing
```

The Manager requests; the **Agent decides at its actual privileged activation point**. The Agent must derive the target ReleaseSet and `sha256:` measurement from **Agent-controlled trusted installed inventory (manifest, OCI image digests, policy/versions)**. It must not accept a Manager-supplied `--measured-digest`, or simply copy a field from the signed verdict. **`verify-activation` verifies the measurement supplied to it; it does not measure runtime artifacts on behalf of the Agent.** The local Lot 1A guard remains mandatory, including rejection of `run_security_gate=false` and `SUCCEEDED`/`SKIPPED` combinations.

## Deployment stages and boundaries

1. **Inventory / pin**: exact source commits, immutable OCI digests, migrations, secrets source, host/kernel/Docker Compose capabilities, trusted Ed25519 public keys and active policy.
2. **Build**: reproducible Konnaxion/Orgo components, SBOM/provenance, owner contracts; neither generic tarball nor a mutable tag acts as proof.
3. **Stage**: place signed composite candidate in private staging; keep active Last-Known-Good and independent DB backups.
4. **Admit**: Agent-owned measured inventory + fresh `PASS` KonnaxionDiag authorization + correct policy/signing authority + protected action scope. No self-sign/override.
5. **Apply**: typed Docker/Compose operations; compatible migrations and reversible orchestration; never claim an atomic transaction across Neon/Orgo databases.
6. **Verify & promote**: exact healthy services, scoped IK receipts, human ACL checks where adopted, durable audit evidence.
7. **Reconcile / rollback**: stop or fence workers first, distinguish `UNKNOWN` from `FAILED`, compensate only known effects, verify trust and restore. Preserve prior valid state.

**Not in scope:** automatic production exposure, onboarding a new OIDC IdP, duplicating Konfid policy engines, direct mutation of other tenants, re-running the FakePlant E2E Apply action, changing kOA-Linux Runtime Pack authority, or replacing owner documentation.
