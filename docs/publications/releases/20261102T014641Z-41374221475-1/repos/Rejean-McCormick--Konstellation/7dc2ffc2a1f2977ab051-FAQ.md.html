# Frequently Asked Questions

### Why only one launcher?

Because the active Kristal should be chosen **inside the application**, not through a different `.cmd` for each domain. `Konstellation.cmd` opens the neutral selector.

### Must Catho be moved next to Konstellation?

**No.** The local example uses `C:\mycode\Kristal\locals\A-Kristal-Catho`, without copying or moving it.

### Can I open any Kristal?

The catalog can detect certain compatible workspaces. The generic reader may show their **v9 structure**, but not every domain artifact has a complete semantic decoder yet.

### Why does “v9” appear if the Framework is at v10?

**v9 defines the semantic state**; the v10 draft preserves it and adds a hosted-network architecture.

### Does Manager decide whether a Kristal is true?

No. Manager performs **operational checks**; the Framework defines conformance, while C1/C2/C3 have separate responsibilities.

### Does `fresh` Discovery guarantee canon integrity?

No. It does not replace verification of Framework semantic commitments or read authorization.

### Does Arketype automatically choose the views?

Its classifications can provide **noncanonical hints**. Konstellation must not treat them as evidence or automatically load suggested code.

### Why is Théophile still present?

It is a historical demonstration/test corpus. Neutral startup should not force users into it.

### Does the local selector depend on Daat or Interaction Kernel?

Not for the demonstrated local opening workflow. Those components cover separate interaction exchanges and mappings.

### Where are authoritative definitions?

In the repositories' **normative schemas and documentation**, not in this introductory wiki. See [[Sources and Status|Sources-and-Status]].

## Why does Konstellation display codes such as `P138`?

A `P…` code is a Wikidata property identifier; it is useful for traceability but difficult to read. In the October 17 French-display patch, some **explicitly known** properties have French display names (for example, `P138` → **Nommé d’après**). Unknown codes remain unresolved and clearly labelled. Raw codes are retained for technical inspection. See [[Semantic Labels and Localization|Semantic-Labels-and-Localization]].

## Does the French-display patch translate every language?

No. It adds a bounded dictionary of French predicate and status labels. It does **not** machine-translate titles or implement a universal multilingual ontology. The English wiki documents the current French UI behaviour.

## Why did searching for `aquin` show Joaquín?

The earlier orientation search accepted substring matches inside longer words. The October 17 patch prioritizes word boundaries and stronger matches. Verify that the patch is installed and that the server was restarted; see [[Astrolabe and Search|Astrolabe-and-Search]].

## Why did a facet disappear?

Empty facets and the routine technical node-kind facet are hidden in normal browsing. An actively selected filter remains visible. The data and the underlying technical relations have not been removed.
