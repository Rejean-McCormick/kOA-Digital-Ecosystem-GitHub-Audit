# Entry Door — Joining KOMPOSE

The Entry Door is the **welcome and admission flow** before diagnostic assessment and role casting. KOMPOSE may present it directly or a partner application may render it under authorized public contracts.

## Target flow

1. The teacher opens a session and generates a time-limited access code.
2. A student enters the code in a school browser.
3. The server checks **identity proof** and eligibility to join the group: the code is not enough.
4. The service creates or retrieves a session-scoped, opaque `participant_id` to avoid duplicates.
5. The participant sees only the minimum relevant information: session state, next available steps, and the public role catalog.

## Required checks

| Scenario | Required behavior |
|---|---|
| Missing, expired, or revoked code | Reject without confirming whether the class exists |
| Unauthorized identity | Deny access server-side |
| Session outside enrollment phase | Reject or resume an already-enrolled participant according to policy |
| Repeated sign-in | Reuse the participant rather than duplicate them |
| Code projected to the whole classroom | Never reveal student names, diagnostics, or private constraints |

## Technical reference

- `src/kompose/entry.py`: local reference rules.
- `POST /sessions/join` in `contracts/openapi.yaml`: **proposed contract**, not a deployed endpoint.
- Session contract: `contracts/schemas/session.schema.json`.

**Still needed:** school SSO, abuse prevention and true concurrent enrollment, secret expiration, institution-scoped authorization, protected audit logs, and accessible responsive UI.
