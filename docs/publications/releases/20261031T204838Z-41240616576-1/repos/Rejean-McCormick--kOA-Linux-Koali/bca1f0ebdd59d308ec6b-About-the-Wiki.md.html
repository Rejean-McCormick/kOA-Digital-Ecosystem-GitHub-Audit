# About This Wiki

> **Reading model:** The main path explains what the kOA ecosystem enables. The technical reference explains how kOA-Linux hosts, isolates, verifies, and operates those capabilities. Product-specific details remain in each subsystem's own documentation.

## Two reading paths

### Main — what it does

The main path explains the social and operational purpose of the ecosystem: knowledge, learning, deliberation, judgment, execution, memory, culture, language, autonomy, and collective capacity.

### Technical reference — how kOA-Linux supports it

The technical path summarizes profiles, components, trust, lifecycle, security, operations, contracts, and conformance.

## Duplication rule

This Wiki should explain the role of independent products but not recreate their internal documentation. Konnaxion, Orgo, SemantiK Architect, Kristal, SenTient, and other systems keep their own repositories or Wikis. This Wiki links to them and documents only the kOA-Linux boundary.

## Authority

The Wiki is explanatory. Repository contracts, accepted decisions, normative source documents, generated catalogs, and validators remain authoritative for kOA-Linux. Product Wikis remain authoritative for their own product-level explanations.
