# Bilan — mise à jour locale Konstellation, 16 octobre 2026

Source **exclusive de départ** : `znapshot_Konstellation_10160729.zip`. Références examinées : Kristal Framework v10 draft.3.2, Authoring Kit 3.3, Manager alpha.14, Arketype, Interaction Kernel 2.0.0-dev.2 et Daat.

## Portée réalisée

- Nouveau lecteur **`kristal-local-v10`**, sur workspace local explicitement indiqué; les états sémantiques internes suivent les schémas v9 du Framework v10.
- Lecture des membres de l'état (vue structurelle) et, si configuré, d'un **modèle de graphe dérivé**. Vérification bornée des chemins, états miroirs, manifestes et empreintes SHA-256 des fichiers canoniques référencés.
- Discovery Authoring Kit vérifié par rapport aux fichiers déclarés lorsque possible. Un profil périmé est écarté de toute spécialisation implicite. Pas de modification des sources.
- Adaptation de My Kristals pour le rapport opérationnel **Manager alpha.14** `--verify-sources` (statut, Discovery, Framework), avec filtrage par les ACL existantes et réduction des données renvoyées au navigateur.
- `READY` d'un inventaire Manager n'est **plus** projeté en `ready` (qui insinuait une qualification); il reste `not_checked` sans preuve indépendante de lecture.
- Un lecteur local configuré est sélectionnable, sans être fusionné par `slug`, titre ou seul `state_ref` avec l'entrée d'inventaire Manager.
- Un lanceur Windows et une configuration d'exemple Catho; code et documentation de l'explorateur existant préservés.

## Validation effectuée

- **21/21 tests ciblés passés** (`tests/kristal-v10`, `kristal-local-v10`, `manager-discovery`).
- Vérificateurs structure Svelte, sécurité frontend, et liens documentaires : aucun problème.
- **Kristal Catho original** : 4 527 entités, 13 217 assertions de projection, `discoveryStatus=stale`, empreintes des entrées canoniques du graphe dérivé identiques, engagement d'état **non recalculé** par ce lecteur.
- **Export Manager alpha.14 réel sur Catho** : 1 entrée, `ATTENTION_REQUIRED`, Discovery `stale`, vérification Framework `NOT_EVALUATED` sans référence fournie; le navigateur ne reçoit ni chemins, ni `issues` complets, ni provenance sensible.
- `npm test` global **non exécutable ici** : dépendances du dépôt absentes (ex. `ajv`) et Node installé `v22.16.0` au lieu de `>=24.15.0`. Aucun test complet Playwright/Windows ni build Astro réussi n'est revendiqué.

## Interaction Kernel et Daat

**Aucun fichier modifié.** IK utilise actuellement un verrou de contrat portable Kristal v6 et une base de conception v7. Ce n'est pas une anomalie pour un lecteur local v10 : IK ne joue pas le rôle de navigateur. Une éventuelle montée de version du protocole IK exigerait sa propre évolution normative et TCK. Daat conserve sa frontière de mapping et d'admission, sans changement requis ici.

## Limites

- **Pas encore un décodeur sémantique v10 universel.** Le nouveau lecteur couvre les états v9 et un format de graphe dérivé explicitement configuré; le lecteur hébergé v10 historique conserve sa navigation technique.
- **Pas de conformance Framework indépendante** : les engagements logiques JCS et la qualification C1/C2/C3 doivent être évalués séparément. Un diagnostic Manager ne donne jamais une permission d'accès.
- **Pas de sync distante**, publication, activation, correction automatique de Discovery ni changement aux dépôts extérieurs.
- **Version livrée : Konstellation 1.0 RC2 + correctif expérimental**, pas une release v10 certifiée. Le gate de release reste obligatoire pour tout tag stable.
