# Runbook d'incident et retour arrière

## I — Manager ne démarre pas après overlay

1. Ne pas déplacer les 127 Kristals.
2. Conserver exception/trace et version Python.
3. Fermer les processus Manager/Diag; sauvegarder le dossier Manager actuel.
4. Comparer l'overlay à l'état précédent; restaurer les fichiers ciblés **depuis la sauvegarde connue**, sans `git reset --hard` aveugle.
5. Refaire tests d'import, scan de trois Kristals, puis 127.

## II — Index opérationnel inaccessible

- Ne pas supprimer `kristal-manager-operations.sqlite3` immédiatement.
- Copier la base, les fichiers `-wal`/`-shm` associés si présents, et les preuves de diagnostics.
- Sur la copie, vérifier `PRAGMA integrity_check` puis version.
- Rétablir une version compatible ou reconstruire sur base vierge **seulement après validation de l'export de l'historique**.
- Un scan peut toujours fonctionner sans historique, mais l'UI doit le signaler.

## III — Diag absent ou JSON invalide

Vérifier `tools/KristalDiag/kristaldiag.py`, `jsonschema` et le chemin du rapport. Une sortie JSON sans schéma attendu n'est pas un verdict. Corriger le moteur/adapter plutôt que le canon pour faire disparaître une erreur d'exécution.

## IV — Tous les diagnostics deviennent périmés

Vérifier si un overlay a modifié `kristal.workspace.json`, un engagement V9 ou un chemin source. Comparer les fingerprints d'entrées avant/après; relancer les diagnostics nécessaires. Ne pas changer `STALE` en `CURRENT` manuellement.

## V — Une publication Git échoue sur une base SQLite

La base est dérivée et doit rester locale; retirer le suivi Git des fichiers, **mais vérifier les commits locaux non publiés** : un fichier supérieur à 100 Mo peut rester dans leur historique et bloquer GitHub malgré un `git rm --cached` ultérieur. Sauvegarder les commits, puis reconstruire un commit propre; pas de push force sans mandat explicite.

## VI — `locals` modifié involontairement

Arrêter les écritures; comparer hash/manifestes et sauvegardes; restaurer uniquement les fichiers identifiés. Refaire Discovery et Diag après retour à l'état cohérent. Ne pas recalculer arbitrairement KQ/KP/empreintes.

## Retour arrière général

Documenter « code précédent + DB opérationnelle précédente + rapports conservés ». Ne jamais effacer les registres de revue ni le canon pour résoudre un problème d'interface.
