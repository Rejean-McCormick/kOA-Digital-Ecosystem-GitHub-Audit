# Glossary

> **Authority notice:** This wiki is a readable navigation layer. Source contracts, accepted ADRs, normative documents, and executable validators in the repository remain authoritative.

| Term | Meaning |
| --- | --- |
| Active authority | The currently activated source contracts, accepted decisions, normative documents, and validation rules for a declared scope. |
| Artifact | A versioned object admitted, verified, activated, transferred, retained, or removed through a declared lifecycle contract. |
| Boundary contract | A machine-readable declaration of responsibilities, exchanges, dependencies, health, resources, security, and prohibited behavior at an integration boundary. |
| Candidate output | Information produced by an optional workbench or external integration that has not been accepted by an authoritative owner. |
| Component | An internal kOA unit whose responsibilities, state, interfaces, failure behavior, and evidence obligations are fully documented by kOA. |
| Contract-first | A documentation model in which source contracts own machine-readable facts and generated indexes provide discovery. |
| Credible exit | The tested ability to export, transfer, restore, self-host, hand over trust, or leave an operator or provider. |
| Generated projection | A rebuildable catalog, index, matrix, manifest, or AI context package with no independent authority. |
| Profile | A deployable selection of capabilities, components, subsystems, resources, connectivity, security, and degradation behavior. |
| Receipt | A machine-readable record of a governed decision or critical transition, including identity, authority, inputs, outcome, and evidence references. |
| Release set | A compatible, verified selection of versioned release-channel artifacts activated together. |
| Safe degradation | Failure behavior that blocks unsafe actions while preserving context, state, evidence, and a declared recovery path. |
| Selective audit | Auditability controlled by purpose, policy, disclosure class, and recourse rather than unrestricted transparency. |
| Subsystem | An independently documented product integrated through a kOA operating and integration boundary. |
| Workspace | A development isolation unit with its own identity, mutable dependencies, services, state, ports, secrets, databases, and resource budget. |

The canonical vocabulary is owned by [`docs/contracts/terminology.contract.json`](../blob/main/docs/contracts/terminology.contract.json). The readable source glossary is [`docs/01-constitution/13-glossary.md`](../blob/main/docs/01-constitution/13-glossary.md).
