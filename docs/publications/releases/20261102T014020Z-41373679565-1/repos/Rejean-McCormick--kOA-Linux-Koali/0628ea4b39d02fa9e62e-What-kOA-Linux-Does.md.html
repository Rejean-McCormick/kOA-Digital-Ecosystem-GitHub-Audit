# What kOA-Linux Operating System Does

> **Reading model:** The main path explains what the kOA ecosystem enables. The technical reference explains how kOA-Linux hosts, isolates, verifies, and operates those capabilities. Product-specific details remain in each subsystem's own documentation.

## Its role in the big picture

kOA-Linux does not implement the entire sociotechnical ecosystem. It provides the sovereign runtime in which selected systems can operate together without collapsing their authority boundaries.

## Responsibilities

- run profile-selected capabilities locally;
- isolate identities, services, stores, networks, keys, and privilege;
- verify and activate software, policy, language, and knowledge artifacts;
- allocate CPU, memory, storage, queues, and background work;
- preserve declared offline behavior and safe degradation;
- provide backup, restore, recovery, export, and credible exit;
- control publication, import, AI, and external-integration boundaries;
- preserve audit evidence and receipts for critical transitions.

## What it does not own

kOA-Linux does not define Konnaxion's civic modules, Orgo's internal workflows, SemantiK grammar construction, SenTient's reconciliation pipeline, Ariane's full navigation model, or UCKK's Moodle internals. Those belong to their owning products and Wikis.
