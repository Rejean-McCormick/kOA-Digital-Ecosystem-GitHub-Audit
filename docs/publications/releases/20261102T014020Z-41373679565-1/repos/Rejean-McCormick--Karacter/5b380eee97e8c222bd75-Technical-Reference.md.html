# Technical Reference — Karacter 7.4

This page summarizes the **current implementation**, not an earlier 4.5 file layout. For versioned contracts and detailed design rationale, use the main repository's `docs/` directory.

## Architecture

Karacter is a **client-side, no-build application** built with plain JavaScript and CSS. `index.html` loads the modules in `src/`. No cloud backend, login, or mandatory external image service is required.

```text
Karacter7/
├── index.html
├── assets/logo.svg
├── src/
│   ├── app.js                 # UI, screens, import/export flows
│   ├── core.js                # Character/workspace model and migration
│   ├── engine.js              # Explainable simulations and prompt logic
│   ├── narrative.js           # Canon events, memory, growth
│   ├── universes.js           # King Klown / Blank Universe alignment
│   ├── seed.js                # Initial examples
│   ├── kristal-pack.js        # Media-derived built-in profiles
│   ├── kristal-integration.js
│   ├── canon-pack.js          # Canon-derived built-in profiles
│   ├── canon-integration.js
│   ├── presets.js             # Twelve starting archetypes
│   ├── batch.js               # Image filename matching
│   ├── storage.js             # IndexedDB and JSON/ZIP backups
│   ├── txt.js                 # Character TXT import/export
│   ├── i18n.js                # FR/EN UI strings
│   └── styles.css
├── data/                       # Bundled JSON source packs
├── fiches/                     # Individual source-derived TXT sheets
├── docs/                       # Product and schema reference
├── tests/                      # Regression & optional UI tests
└── package.json
```

## Key data structures

A *workspace* contains characters, universes (collections), relationships, scenarios, simulation runs, comparisons, story events, visual themes, image metadata, and preferences. The stable **character ID** is the link target; display names can change.

A polarity stores a left score in **0–6**, and the right score is derived as **`6 - leftScore`**. Meaning is contextual; no moral ranking follows.

## Persistence model

**IndexedDB** is authoritative for the active workspace and image assets. Ordinary edits are coalesced; critical operations (image and workspace changes, deletion, full restoration) use transactions. Save-state feedback reports pending/saved/error. A small legacy localStorage reader is retained for one-time migration from older releases; localStorage is not the current primary workspace store.

## Backup formats

- **Application 7.4** exports **KaracterBackup schema v6** intentionally.
- Complete JSON includes workspace plus base64 image assets with SHA-256 integrity metadata.
- Complete ZIP contains an application JSON backup plus supporting TXT sheets and prompts.
- Individual TXT exports use `KARACTER CHARACTER SHEET v6` and include machine-readable JSON, but no artwork bytes or shared story timeline.

Custom compressed ZIPs may be unsupported by the built-in reader. Prefer an export generated by Karacter itself or import the extracted JSON.

## Tests

From the app root, with Node.js 20+ installed:

```sh
npm test
```

The `npm test` script runs the included Node-based model, narrative, storage, pack and universe tests without `npm install`. Optional Python browser smoke tests require a compatible Playwright/Chromium setup.

**Caveat:** isolated browser tests and IndexedDB test doubles do not certify persistence after a real browser is closed and reopened; test this on the actual target device.
