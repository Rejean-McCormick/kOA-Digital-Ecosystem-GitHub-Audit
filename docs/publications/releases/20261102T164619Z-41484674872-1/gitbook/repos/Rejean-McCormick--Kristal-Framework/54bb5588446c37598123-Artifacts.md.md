# Artifacts

Kristal v9 distinguishes **logical authority** from **physical representation**.

## v9 core artifacts

### Logical Artifact

Domain-native logical knowledge governed by a named `logical_contract` and protected by a Logical Commitment.

See [[Logical-Artifacts]].

### State Snapshot

Immutable composition of owned Logical Artifacts and pinned external references.

See [[State-Snapshots-v9]].

### Derivation

Build-lineage record describing declared inputs, transform, parameters/toolchain and outputs.

See [[Derivations-and-Reproducibility-v9]].

### Materialization Manifest

Binds one exact source Logical Artifact commitment to physical blobs/segments under a named materialization profile.

See [[Materialization-v9]].

### Exchange

Portable/verifiable packaging of a State Snapshot and materializations.

See [[Exchange-and-Runtime-v9]].

### Activation record

Operational pointer transition selecting a published immutable State Snapshot. Activation is not part of the logical state itself.

See [[Build-Publish-Activate-v9]].

## Preserved v6/v7/v8 artifacts

### v6 Kristal State

`kristal_state/6.0` remains a valid portable epistemic artifact.

### v7 registries / Mesh

KQ/KP/KA/KS registries, Mesh/KOS mappings, axes and projections remain the semantic identity/orchestration substrate.

### v8 lexical/query companions

Lexical Kristals, lexicon stacks, query indexes/results and AI context bundles remain read/access-side artifacts.

## Derived/read artifacts

Examples:

- AI context bundles;
- local dictionaries;
