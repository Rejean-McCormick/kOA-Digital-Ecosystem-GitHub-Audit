# Learner Experience

## Experience goal

A child should feel: **“I belong to this team. My ideas are useful. I can ask someone, help someone, and learn something.”** Akor should make collaboration legible at the age of the learners, not impose an adult project-management UI.

## Suggested mission screen

```text
┌────────────────────────────────────┐
│ Village Bakery                     │
│ Your role: Baker                   │
│ Our mission: Prepare the order     │
├────────────────────────────────────┤
│ What I know                        │
│   [One short instruction]          │
│                                    │
│ What I can do                      │
│   [Arrange trays] [Ask for help]   │
│                                    │
│ What we need together              │
│   [Ask the farmer about supply]    │
│                                    │
│ My team                            │
│   Farmer: working / available      │
│   Accountant: waiting for plan     │
├────────────────────────────────────┤
│ [Share my result] [Back]           │
└────────────────────────────────────┘
```

**This is a storyboard**, not a screenshot or an implemented interface.

## Principles for child-facing content

- Present one clear action at a time; break complex instructions into useful small steps.
- Use child-appropriate vocabulary, pictograms where validated, and a readable large target area.
- Show the **group's shared purpose** and the learner's **personal contribution**.
- Make help safe, obvious and without stigma.
- Treat mistakes as opportunities to reason again, not public failures.
- Do not expose other children's private status, grades, support settings or answers.
- Minimize timers, speed comparisons and disruptive animations.
- Support keyboard access, alternatives to drag-and-drop, and various input modalities.
- Avoid using a free-form unmoderated chat by default.

## A meaningful progress indicator

A group timeline can show **what the team has achieved** without labeling children as good, bad, fast or slow. Progress should reflect Orgo-approved task state; individual learning evidence remains private in Ekole.

## Solo, pair and team

A **solo mode** can preserve role narrative and the same Orgo runtime, but without pretending that real peers are present. A teacher-facilitated pair can complete a mission together without requiring separate devices. Group mode adds carefully controlled interdependence and communication.

## Degraded mode

If Orgo is unreachable, the learner should receive an understandable message such as “This mission is temporarily unavailable. You can return to your lesson.” Do not mark contributions complete locally and silently synchronize later unless there is a separately designed, authorized offline protocol.
