# Internal kOA-Linux Components

> **Reading model:** The main path explains what the kOA ecosystem enables. The technical reference explains how kOA-Linux hosts, isolates, verifies, and operates those capabilities. Product-specific details remain in each subsystem's own documentation.

Internal components are fully owned by the kOA-Linux documentation corpus.

| Component | Purpose |
| --- | --- |
| Audit Broker | route and selectively preserve audit and evidence events |
| Governance Policy Runtime | evaluate authorization, disclosure, consent, privilege, and governed exceptions |
| Identity and Trust | identities, credentials, trust roots, and relying-context results |
| kOA Mediatheque | local media and file authority |
| kOA Node Agent | narrow host lifecycle, activation, health, recovery, and privileged operations |
| Kristal Runtime | verify and expose activated Kristal artifacts locally |
| Publication Gateway | authorize governed cross-domain disclosure |
| Resource Governor | deterministic resource limits, queues, concurrency, and pressure control |

The UCKK adapter is an external-integration bridge, not a local media owner. Konnaxion, Orgo, Ariane, SenTient, and SemantiK Architect are independently documented products, not internal components.
