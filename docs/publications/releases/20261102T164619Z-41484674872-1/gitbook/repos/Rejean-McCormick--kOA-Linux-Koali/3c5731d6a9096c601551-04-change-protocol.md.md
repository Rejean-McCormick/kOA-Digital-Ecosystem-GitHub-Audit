# Change Protocol

## 1. Procedure

Edit the owning source, update affected boundary contracts and tests, run impact analysis, rebuild generated outputs, validate, and activate one coherent documentation release.

## 2. Subsystem Changes

Internal subsystem changes occur in the subsystem documentation. kOA changes only when the operating boundary, compatibility, deployment, or interaction contract changes.

## 3. Review

Review focuses on ownership, scope, compatibility, generated drift, and executable validation rather than synchronized inventory edits.
