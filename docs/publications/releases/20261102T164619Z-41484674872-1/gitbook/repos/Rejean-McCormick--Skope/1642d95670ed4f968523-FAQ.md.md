# Frequently asked questions

### Can Skope enrich 104 Kristals without a separate bridge?

It now has a **native `skope portfolio` CLI** for preparing a v11 portfolio. It can inventory, discover candidates, acquire complete source records and produce **noncanonical** enrichment proposals. No separate Skope–diK bridge is required for those steps. The diK crosswalk approval and Authoring Kit publication integrations are **not** implemented in Skope. See [Portfolio Enrichment](Portfolio-Enrichment).

### Does a unique label match mean Skope has approved a Wikidata QID?

No. `suggest-draft` uses bounded exact name hits to produce **unverified** working seeds, and excludes `A-Kristal`. It never creates an approved `exactMatch` identity.

### Can I enrich a Kristal directly from the compact SQLite index?

Not with original claims and references. The index supports discovery; `portfolio acquire` needs a verified full dump, working source profile and fast random-access locator. It will not download the dump automatically.

### Can I publish the new Kristals automatically from Skope 0.15?

No. `propose` writes working full-claim proposals, not canonical KAs or new Kristal versions. diK and the Authoring Kit are still separate validation/publication steps.

### Does the ZIP install a complete Wikidata database?

No. It contains code, configuration, fixtures and tests, but not the large finished SQLite index, full dump or access sidecars.

### Is Skope fully offline?

Core discovery and analysis use local files. The program's batch identity ranking does **not** fetch documentary web pages. The term “offline-first” does not imply that source files appear automatically or that external sources were verified.

### Does `Calculate scope` collect all matching QIDs?

No. It produces a bounded preview (at most 10,000 nodes). Collection requires an explicit, separate disk-backed job.

### Can I use `direction: both` for QID collection?

No. The preview validator permits `both`, but the batch collector requires a single direction and explicit property filter.

### Does `max_entities: 0` remove all limits?

It removes the **requested mass-job QID cap**, not the HTTP preview limit. A large export becomes a **plan ZIP**, not a complete inventory.

### Does a Canada-prioritized scope include only Canadian taxa?

No. Mass collection does not filter by geography; even preview geography is derived from incomplete, bounded indexed signals.

### Can Skope automatically build the random-access index if it is missing?

No. Full extraction fails preflight if required existing source access components are absent.

### Are recognized Catho names necessarily the right Wikidata identities?

No. Recognition source context does not establish a particular QID identity. Human review and corroborating documentary material remain essential.

### Does an identity score of 90 mean 90% certainty?

No. It is a weighted heuristic number with no calibrated probability interpretation.

### Does confirming a batch update Kristal or download new works?

No. It writes Skope-local decisions and audit entries only. Further acquisition/import is separate and explicit.

### Is a full Wikidata record guaranteed accurate?

No. It preserves what the referenced Wikidata dump contains, including its claims and references, but those may be missing or incorrect.

### Does the official source verification run over the 96 GiB dump every time?

No. Preflight checks an existing verified manifest and metadata rather than rehashing the entire dump on every extraction.

### Can I expose Skope as a public service?

Not as configured. The service enforces loopback access and has no intended public-user authentication boundary.

### Which release is this wiki for?

Source/backend release **0.15.0-alpha.1** (`pyproject.toml`: `0.15.0a1`). Historical README sections still mention older milestones. See [Known Limitations](Known-Limitations).
