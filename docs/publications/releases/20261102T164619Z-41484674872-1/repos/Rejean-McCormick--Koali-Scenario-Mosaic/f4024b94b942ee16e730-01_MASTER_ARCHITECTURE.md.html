# Master architecture for presenting Koali uses

## 1. Communication problem

Koali is highly versatile. That creates two opposite risks:

- if we say **“Koali can be used almost anywhere,”** it sounds vague;
- if we show only concrete examples, readers may mistake Koali for a vertical application in the example sector.

The presentation must therefore show **specific situations and the transferable pattern behind them at the same time**.

## 2. Presentation stack

### Layer A — Promise

> **Koali connects what an organization knows with what it does.**

Expanded:

> Koali connects knowledge, people, choices, work, outcomes, and memory so context does not disappear between understanding and action.

### Layer B — Usage palette

Use eight human-facing families:

**Find & Understand · Learn & Share · Collaborate & Create · Choose & Govern · Organize & Act · Respond & Coordinate · Remember & Improve · Disseminate & Connect to the Public**

These are navigation categories, not product modules.

### Layer C — Hero scenarios

Show 12 sharply different situations before explaining technical architecture. The goal is recognition: *the contexts are different, but the continuity problem is the same*.

### Layer D — Pattern families

Introduce 24 recurring patterns between the broad palette and the detailed scenarios. Examples: investigate a signal, find the right expertise, deliver work with context, maintain a changing shared situation, turn action into a lesson, explain publicly without severing sources.

### Layer E — Component lenses

Only now explain the main contributors:

- **Kristal** — semantic knowledge, provenance, relationships, versions, memory.
- **Konnaxion** — people, learning, contribution, collaboration, deliberation, discovery.
- **Orgo** — cases, responsibilities, routing, tasks, dependencies, verification, closure.
- **UCKK** — education and multimedia dissemination when knowledge must reach a wider audience.

EkoH / Smart Vote, SemantiK, AI assistance, local/offline infrastructure, and hardware profiles appear as secondary or cross-cutting lenses where relevant.

### Layer F — 120-scenario Atlas

The Atlas demonstrates breadth. It does not define Koali. Every scenario is tagged by:

- primary usage category;
- recurring pattern family;
- usage palette;
- component intensity;
- entry trigger;
- scale;
- setting;
- cross-cutting properties;
- domain;
- canonical references;
- derivation and runtime evidence.

## 3. The invariant

The scenario changes. The invariant is continuity:

`signal / question / goal → context → people → choice → work → result → memory → renewed knowledge`

Not every scenario uses every step, and some loops start in the middle. What matters is that Koali can keep the identity and context of the work connected across the steps that do occur.

## 4. What not to do

Do not lead with a list of 120 professions. Do not lead with module names. Do not imply that every scenario is a validated deployment. Do not describe Koali as replacing certified or specialist systems when its role is actually context, coordination, knowledge, evidence, and memory around those systems.

## 5. Desired reader progression

**10 seconds:** “I understand the basic problem.”

**2 minutes:** “I see that this applies in very different contexts.”

**5 minutes:** “I understand the recurring patterns and why this is one system rather than many unrelated tools.”

**Deep exploration:** “I can find a scenario close to my own situation and inspect which Koali capabilities are relevant.”
