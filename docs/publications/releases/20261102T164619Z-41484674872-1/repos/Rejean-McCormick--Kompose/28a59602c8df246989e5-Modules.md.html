# Nine Functional Responsibilities (Design, Not Deployed Services)

| # | Area | KOMPOSE reference role | Details |
|---|---|---|---|
| 1 | Entry Door | Models a time-limited code **plus externally authenticated identity** | [[Entry-Door]] |
| 2 | Diagnostic | Defines assessment and fairness constraints; no validated adaptive engine | [[Diagnostic-and-Role-Casting]] |
| 3 | Role casting | Optional first-third policy; teacher-supervised *proposals*, no production solver | [[Diagnostic-and-Role-Casting]] |
| 4 | **Local coordination simulation** | State models, mission dependencies and fictional prompts; **Orgo runs real Tasks** | [[Missions-and-Events]] |
| 5 | Kristals | Versioned documentary knowledge, source controls and scripted answers | [[Kristals]] |
| 6 | Interactions | Fictional cooperative prompts, not a live messaging system | [[Capsule-Journey]] |
| 7 | Adaptation | Design for accessible alternatives and pacing | [[Security-Privacy-and-Fairness]] |
| 8 | Supervision | Proposed teacher console, privacy rules, human approval | [[Teacher-Console]] |
| 9 | Closure | Simulated completion and intended retention safeguards | [[Operations-and-Incidents]] |

The original module vocabulary is a **functional model**. It does not imply nine microservices, operational IAM, or a second production workflow engine. The current B6 and P1 validators are described in [[Kontexte-B6-Preview]] and [[Ekole-P1-Preview]].
